# Telegram Ads automation MVP

Асинхронный worker управляет активными объявлениями одного Telegram Ads
кабинета: отслеживает подозрительный трафик, небольшими шагами пополняет
бюджеты и раз в несколько часов корректирует CPM по CPA. Telegram-бот служит
пультом управления и показывает только агрегированную статистику, баланс,
настройки и важные события.

При первом запуске **общий переключатель автоматики выключен**. Worker уже
собирает снимки статистики, но не вызывает методы Ads API, изменяющие деньги,
CPM или статус объявления. Включение выполняется из раздела
`⚙️ Автоматика` после проверки показателей.

## Запуск

1. Скопируйте `.env.example` в `.env` и заполните:
   `BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ADS_API_TOKEN`, `ADS_ACCOUNT_ID` и
   `POSTGRES_PASSWORD`.
2. Запустите приложение:

   ```sh
   docker compose up --build -d
   ```

3. Проверьте состояние:

   ```sh
   docker compose ps
   docker compose logs --tail=100 migrate bot worker
   ```

Compose поднимает PostgreSQL, применяет Alembic-миграции, затем запускает
отдельные процессы бота и worker. Данные PostgreSQL хранятся в именованном
томе `postgres_data`; обычный `docker compose down` их не удаляет.

Для локального запуска установите зависимости через `poetry install`,
задайте переменные окружения, выполните `poetry run alembic upgrade head`,
а затем запустите `poetry run python -m app.bot.main` и
`poetry run python -m app.worker.main` в отдельных терминалах.

## Правила по умолчанию

- мониторинг: каждые 5 минут;
- FraudGuard: 15 минут, не менее 20 000 новых views, расход 0.50 TON и
  ни одного action;
- target CPA: 0.25 TON;
- оптимизация CPM: каждые 6 часов по последним 72 часам;
- CPM: диапазон 0.10–1.00 TON, изменение на +5%, −5% или −10%;
- бюджет: порог 0.02, шаг 0.10, дневной лимит автопополнений 1.00 TON на объявление;
- резерв кабинета: 1.00 TON;
- после изменения CPM следующий пересмотр объявления блокируется на 90 минут.

Объявления без `action_type` остаются только под наблюдением: их CPM, бюджет
и статус worker не меняет. Fraud-блокировка запрещает последующие пополнения.
Кнопка снятия блокировки в боте не возобновляет показ объявления.

Начальные значения рассчитаны на TON. Для кабинета в другой валюте общий
переключатель не включится, пока правила не будут адаптированы.

## Безопасность и восстановление

- Секреты читаются только из окружения и не записываются в логи или БД.
- Каждое изменение сначала фиксируется в `automation_actions`.
- Пополнения используют сохранённый idempotency key и безопасно повторяются
  только в пределах 24 часов.
- Неоднозначный результат изменения CPM/статуса проверяется повторно после
  периода применения Telegram Ads.
- PostgreSQL advisory lock не позволяет двум worker одновременно управлять
  одним кабинетом.
- Старые таблицы предыдущего прототипа не удаляются миграциями.

## Тесты

```sh
poetry run pytest
```

Интеграционные тесты PostgreSQL выполняются при наличии
`TEST_DATABASE_URL`; обычный набор тестов не обращается к настоящему
Telegram Ads API и не изменяет объявления.

Локально тестовую PostgreSQL можно поднять отдельно от рабочих данных:

```sh
docker compose -p tg-ads-bot-test -f compose.yaml -f compose.test.yaml \
  --env-file .env.example up -d db
TEST_DATABASE_URL=postgresql+asyncpg://tg_ads_bot:replace_with_a_long_random_password@localhost:55432/tg_ads_bot_test \
  poetry run pytest tests/integration
```
